# Developer tooling

Run these commands from the repository root with Dart 3.13.5 on macOS/Linux ARM64. [Build the native compiler](../README.md#build-from-source) first; bootstrap verifies and saves `build/dartc-seed` for subsequent runs.

## Compare compiler performance

Compare two existing native compilers on the same compiler task:

```sh
dart tool/benchmark.dart --compare /path/to/baseline /path/to/candidate
```

Running `dart tool/benchmark.dart` without `--compare` builds a separate official AOT reference. Reference binaries never become bootstrap seeds.

The report records elapsed time, user/system CPU time and kernel peak RSS. Each task uses a fresh sampling process; sampling driver startup and bookkeeping are excluded. Unavailable metrics remain null. Peak RSS is the maximum child high-water mark, not total concurrent process memory.

Comparisons require unchanged compiler/runtime inputs and identical generated bytes. Code generation changes need separate behavior and performance comparisons.

## Differential testing

Generate bounded integer/boolean expressions and constructor interactions:

```sh
dart tool/fuzz.dart --seed 1 --count 20
```

Each case compares the SDK oracle, SDK-hosted dartc and native dartc. Failures retain the actual sources, dependencies, commands and a frozen compiler/runtime/tool snapshot under `build/fuzz/`.

To investigate a saved failure:

1. Run the printed replay command. It uses the recorded files rather than regenerating a program from its seed.
2. Add `--shrink` to that command to reduce a generated case. Reduction requires a stable failure and a saved model that matches the source.
3. Check a repaired compiler against the saved case:

   ```sh
   dart tool/fuzz.dart --compiler /path/to/repaired-dartc --case /path/to/saved-case
   ```

Use `dart tool/fuzz.dart --help` for explicit rejection and runtime-failure contracts.

## CI

The [native self-hosting workflow](../.github/workflows/native.yml) is manually dispatched. It bootstraps on Linux ARM64, runs differential, resource-measurement and fuzz tests, and cross-compiles the compiler for macOS. Release packaging and verification are optional workflow inputs.
