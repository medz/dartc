# dartc 任务看板

本看板维护尚未完成的工程任务、依赖与验收条件。实际执行范围由当前任务指令确定。

## 现在从哪里开始

**完成目标是 T13 的本机默认产品验收。** 在 macOS ARM64、Dart 3.14.0 上用默认 CLI 和公开 Compiler API 编译同一份固定源码，执行产物并核对可观察结果。交接版本为 `3e1cd203`，已验收的基线编译器为 `33fb01d7`。按输入分别记录通过、失败和超时。

**当前优先解决默认编译无法完成。** 先让固定普通源码经 CLI 与公开 API 生成能在本机执行的产物并核对结果，优先处理抛错、求解不收敛和真正阻止生成的依赖。可执行结果出来后再比较性能。一次限时未产物只标记超时。对已知长路径，预先设置足以观察原故障的单次时限、CPU 时间和 RSS 上限，并记录终止及进程回收。

当前已能编译的最小对照是普通导出 `int increment(int value) => value + 1`。提交 `6711d10f` 的默认 CLI 和公开 `Compiler.compile` 均生成 49888 字节的同名共享库，文件 SHA-256 相同。分别加载两份新库后，五个有符号整数在两个入口均返回 value + 1。用此结果区分工具链整体故障和特定程序的求解或生成故障。原始打印与同堆输入仍有各自的验收条件。

## 任务如何完成

- 状态只在本页维护：待领取、进行中、受阻、待验收、已暂停、已交付。领取时填写执行者、非作者验收者、实际输入版本和编辑范围；受阻时写清缺失产物及解除条件。执行/验收栏记录当前状态；未领取项不代表目标范围被删除。
- 卡片的结果包括真实消费者、调用方/导出/fixture 迁移、相关规格和替代路径删除；缺项回到原卡处理。依据[独立审查门](workflow.md#独立审查与驳回)取得绑定实际版本和范围的接受结论后才能标为已交付。
- 依赖表示所需的可消费合同或产物，不要求等上游整卡结束。接口必须共同改变时统一整合责任，循环依赖应重新切分。
- 每项采用[基础能力验收合同](layout.md#基础能力先统一)和[测试分组](../../test/README.md)，保存可复核证据。卡片中的源码观察用于定位工作，不构成运行结果或性能测量。

## T01

**结果：后续进展能由同一默认产品的行为和实际产物判定。**

- [bench](../../tool/bench.dart) 的报告往返、回退比较、输出排空、超时与失败记录、输入指纹及配置校验已获限定接受。真实默认基线、保留归因和平台成本仍待完成；CPU/RSS/短进程启动测量采用适合平台的现有工具，不能把粗采样当真实峰值。
- 复用 object/符号/节读取，核对必要操作的机器指令、装箱、调用/搬运、内存访问与循环成本，并把体积归到机器码、数据、根/帧/类型/资源及真实保留原因。需要的分析观测接入事实拥有者，不添加仅为测试的生产开关或新测试平台。
- 固定 [T13](#t13) 的默认源码、运行时输入和预期，为后续任务建立同一基线；用 managed_globals、回调及库 FFI 客户端验证重复入口，单 main 中保留的对象不能替代持久库入口。
- 验收：自己的报告能正确发现时间/体积回退，失败/挂起不报绿，默认二进制可追溯；有初始真实依赖链和当前失败分类。默认/诊断、编译耗时/运行耗时、原生/模拟明确区分。只在实际测量后填数字；后续任务沿用同一组输入。

## T02

**结果：用户、std、runtime 在同一 FFI/C 表示基础上得到正确且成本可解释的基础执行；solver 和机器层消费同一份效果与 GC 阶段合同。**

- 先按值/操作核查当前底座：标量位宽/算术、地址、布局/对齐、读写与别名、直接/间接调用及聚合参数/返回。对照普通 Dart 与 FFI 的实际生成路径，找出重复表示、包装、调用搬运和隐藏分配；现有 NativeLayout/ABI/PointerRepresentation 作为比较输入，不默认正确，也不预建全新底座。
- 按发现的共同缺陷交付具体基础能力及全部消费者，覆盖 user/runtime 必须实际运行的调用和存储；同时查看对应生成操作、编译/运行成本。与 T10 交接明确的值、调用、布局和追踪合同，不能仅修补注解后宣称底座扎实。
- 完成 IrExternal 的结果、effects、memory、终止、逃逸及 noGC/no-reentry 合同和必要环境/失败事实；约束语义见 [runtime](runtime.md)。
- 将 bootstrap/control/managed 阶段、独立控制存储及其托管引用扫描责任显式化；普通 Pointer/Struct/FFI 与 runtime 共用底层规则，受信来源和签名继续检查。
- 以 native_storage、codegen/runtime、runtime/heap 与弱引用/终结夹具验收：控制区/用户堆分配失败、收集期间意外分配/重入、隐式 Pointer 包装、控制区引用存活。保留受控收集测试，不能要求弱引用按某一语言时机清空。
- 删除被替代的重复登记/来源待遇和机器层算法副本；已有普通 Dart GC/noGC 按合同复用，发现算法或执行形态缺陷时修改其实际拥有者。OS 叶子接入比较已有 FFI 与必要机器原语；不因来源或 API 名称建立特例。

## T04

**结果：程序入口的真实行为可被共同分析，正常、失败和重入生命周期一致。**

- 将 [codegen](../../lib/src/codegen/) 的 fresh/persistent/reentry 入口和调度行为作为可分析的实际程序：初态、main、初始化、事件/保活、exitCode、释放、卸载、正常与异常退出。明确模块状态所有者，保留进程 exit 的立即终止语义。
- 消费 T02 的 GC/control 阶段和 T03 的状态摘要，不能把所有库入口当全零新进程；后端只保留 SP/PC、帧/根接点和必要系统叶子。
- 验收 process_lifecycle、managed_globals、native_callables、native_callbacks/native_callbacks_ffi 的默认源码及固定 FFI 客户端：重复入口、最外层/内层活根、初始化失败再试、timer/异常退出、卸载清理。
- 将生命周期语义交给普通 IR 统一持有，迁移编译器和独立入口调用方，并验证机器层没有并存算法。异步宿主驱动/多线程属于后续明确合同，不把尚未支持的边界伪装成已支持。

## T05

**结果：语义程序、基础能力的执行形态、生成支持和程序改写共同闭合；基础成本改善与短路径均在默认编译入口成立。**

交接候选将 [Compiler](../../lib/src/compiler/compiler.dart) 和[准备入口](../../lib/src/codegen/program_preparation.dart) 迁移到共同执行事实与显式闭合检查。各支持家族的真实调用、状态接入和默认消费者仍须整体验证。

- 将现有构造/全局/late/闭包/record/类型/ABI 等支持家族需要的实际调用、参数、返回、类型环境、状态和异常区带回同一 IrProgram；区分语义支持与冻结后纯机器接线，不能一律提前展开整个 runtime。本卡从 T02/T10 的实际基础与表示消费者闭合支持家族，不将旧形态固化为接入前提；T10 先交付对应的可消费能力和行为，T05 收尾它们与状态/入口的共同反馈及默认整链验收。
- 同一负责人收尾 Compiler、ProgramOptimizer、ProgramPreparation 及相关生成消费者；生成体新增/替换后重解真实 entries，失效旧 facts/layout/selection。评估现有 pass 和图身份检查是否满足共同循环；复用有效部分、替换错误边界并删除旧驱动，不并存同责求解器。
- 默认 compile 和公开 prepare 遵循同一合同；固定图上的依赖扩展与 IR 改写后的重分析分开。目标/配置/入口/IR 共同决定 prepared，发码发现漏依赖明确失败。
- 验收 prepared_program/program_optimizer 的真实消费者及默认 CLI：函数数量不变但目标/实参改变、新支持体引入后旧证明失效、需求消失后支持体可删除。用携带实际语义的共同分析取代仅传目标名、放宽参数的补依赖协议；保留对真正运行时未知的正确处理。支持体仍须通过 typed IR verifier。

## T06

**结果：正常返回和控制流证明能安全简化真实调用者。**

- `checkIndex(x)` 的正常出口可约束后续 x，catch 路径不得取得该证明；合流、别名写入、循环重入和图替换后重建事实。复用 FlowSource/summary、分支约束与 FunctionRewrite。
- 如必须新增证明载体，构造、验证、remap 和最终消费者同批完成；普通 SSA 足够则不用新 IR；图替换、重新定型和引用重映射必须完成验证及事实失效。
- 验收 integer_paths、integer_range、program_flow、loop_specialization，以及 guard/跳过检查的源码反例：检查后的分支实际消失，失败路径、异常身份和副作用保留。
- 删除重复或失效的证明传播路径；静态错误在未执行代码中仍拒绝。最终经 T05 的默认入口再验证，不能仅凭手造 IR 声称源码已支持。

## T07

**结果：有限已知循环正确简化，并在可说明的编译成本内得到剩余执行。**

- 测清已有 LoopRanges/peeling/简化的成本；需要共同求值时复用相同算术、异常和状态规则，不增加一份库解释器。预算耗尽正确保留原循环，不改变未知或可能不终止的行为。
- 使用 finite_loops/loop_specialization，并覆盖循环求值反例：出口参数、循环外使用、嵌套重入、wraparound、break/catch/finally、KeepAlive 和真实 IO/全局写入。
- 验收默认配置下已知累计/字符串计算能变为更直接的执行，未知次数仍正确；比较改写后的程序/产物与编译成本，不用少执行副作用换倍数。
- 删除被共同机制取代的重复 peeling/求值代码；求值预算须有默认真实输入的成本依据。

## T08

**结果：已知调用行为可以形成独立残余函数，无须成功内联才能获益。**

- 消费稳定 activation/summary，真实调用点改接受预算约束的残余体；保留声明身份、泛型环境、函数值身份、异常帧/内联链和开放边界的正确通用实现。
- 使用同一 FunctionRewrite、调用绑定和失效流程；递归实例、tear-off、callback 和 metadata 一起迁移。内联按实际残余成本决定，而非单纯调高阈值。
- 验收两个超过默认内联阈值的不同已知调用仍能分别简化；开放调用、函数值覆盖、lexicalTypes/boundValue/multipleCaptures 和泛型参数检查保持正确。
- 实例化复用统一图变换与验证合同；实例键、收敛与预算先用真实输入比较，不能无限按常量值克隆。

## T09

**结果：没有剩余观察义务的普通对象、存储及其连带支持一起消失。**

- 扩展现有 storage promotion/elimination 和简化消费者；以真实读写、别名、身份、逃逸、初始化、副作用及异常事实证明。Map/ThreadLocal 是输入样本，不能成为名称特判。
- 复用 object_state_flow、storage_promotion/elimination、raw_storage_elimination；覆盖同等普通用户容器的反例：重复/null/数值键、读前写、闭包捕获、迭代/修改、throw/await/yield 与逃逸。
- 验收默认源码：存储消失时，必要构造效果、final 检查、OOM/终结存活等公开义务和顺序仍正确；关联初始化、类型/helper 需求经 T05 重新收敛。确实需要物化的对象保持正确实现。
- 删除被一般机制取代的局部消除规则和无效保留集合；对象消除采用统一存储与观察义务证明。

## T10

**结果：必须执行的函数、对象、闭包和类型操作在共同基础上具有合理形态，其质量不依赖成功内联、常量折叠或对象消除。**

- 消费 T02 的对应基础合同，比较源码声明身份与物理入口、语言类与存储布局、类型语义与执行数据的关系。[ProgramLayout](../../lib/src/codegen/program_layout.dart) 当前按声明类型选择普通入口/返回表示、附加 TypeMetadata，并按 declaration 缓存类布局；核查这些选择及[后期转换](../../lib/src/codegen/function_representation.dart)中装箱、泛型字段检查的实际用途和成本，不预定全部单态化、全部共享或另一套固定对象模型。
- 使用 runtime 值变化、保留下来的普通/泛型调用、存活对象/闭包和真正多态的输入；以 Zone、Object.toString、集合及同等用户实现检验共同机制。逐项检查调用、读写、类型操作与循环的实际生成质量；必要时修订普通 Dart runtime 算法和数据结构，不以 API 名称生成专用路径。
- 通过默认 Compiler/CLI 或已有公开 prepare 的真实消费者交付值表示、调用入口、读写与必要支持体，保持身份、别名、泛型检查、可观察 Type/runtimeType、GC 和 FFI 合同。支持体携完整调用与类型/状态关系，并通过 typed IR 验证；T05 负责新增行为进入共同循环的整链验收，本卡不等待 T08/T09 完成。
- 验收 program_layout/type_relations/pointer_representation 及实际泛型、对象、动态输入、FFI；使用 T01 对应输入核算必要执行的指令/存储/依赖及成本。表示变化同时失效选择/分配/根/metadata，所有共享槽访问者采用一致合同。正确的语义、成本改善及剩余成本原因分别报告。
- 删除替代后的声明到物理形态绑定、重复状态和无用模板；沿用同一普通 Dart 类型算法与底层规则，不能另建一份后端 runtime。T08/T09 的后续简化继续消费本卡能力，不能替代本卡验收。

## T11

**结果：必要 GC 根与同步/异步堆栈信息准确且紧凑。**

- 沿用机器选择→独立 FunctionAllocation→实际 PC；依据实际 GC、调度和线程协议确定安全点，核对循环携带引用及调用/异常/暂停/回调的活根位置，不预设每条回边必须增加轮询。只在证明机器约束满足后减少保存，不直接删 spill。
- 分别核对源码位置/帧描述、内联链、异步父链与 GC 根布局；复用已有共享，再按实际产物决定共享/编码。metadata 不反向保活已删代码，也不能混淆 GC 与可观察栈信息。
- 验收 stack_maps、stack_roots、async_stack_traces、native_callbacks、Finalizer：循环携带引用、critical edge、并行交换、异常边、重入和强制 GC；活跃非 Instruction Value 的来源信息继续保留。
- 用 T01 的实际 PC/节/符号核算真实收益与解码成本，保留失败栈行为。删除旧重复布局/描述集合；不把理论去重差额当实际收益。

## T12

**结果：机器位置和边/调用搬运减少真实执行成本，并保持 GC/ABI 正确。**

- 比较当前独立 FunctionAllocation 的跨块 homes、寄存器约束、edge copies、call save 和 spill 的实际代价，再选择是否需要区间拆分或其他算法。
- 同时看整数/浮点循环、多态调用、对象引用循环和固定/冲突寄存器；按现有分配合同和 checker 扩必要验证，不扩为通用机器测试平台。
- 只有在实际对应程序改善且语义、GC 根、ABI、编译成本与体积得到说明后接收改变；若瓶颈在 T07–T09 的额外工作，先消除它，不为打勾重写分配器。
- 保持目标无关位置结果与具体 ARM64/x64 发码职责；受影响平台实际执行，模拟时间不宣称硬件性能。

## T13

**结果：当前里程碑以默认产品完成，而不是以内部接口或局部样本完成。**

- 固定默认源码与预期：Hello/42–43、未知输入、Zone/toString、fromCodes、对象与集合、泛型/函数值、typed catch、GC、重复入口/回调、system_libraries。用真实运行时值变化、Zone 行为实际执行、泛型调用保留、对象必须存活，以及具体类型已知与真正多态两类输入，分别验收必要执行质量和可推导短路径。已知静态错误在死代码中仍拒绝。
- 对每个未完成编译给出具体阶段/图规模/剩余依赖与可复核原因；保留一个最小反例，归回对应任务，不能换简单文件、增加超时或关闭检查获得绿色。
- 默认 CLI 与 Compiler API、object/static/shared/executable 的受影响路径共同验收；本轮在 macOS ARM64 原生执行。受影响的 Docker Linux ARM64/x64 和本地无法证明的必要 CI 目标留给后续跨平台验收。
- 最终报告同输入/配置的行为、代码/数据/metadata/依赖、编译/运行时间与 CPU/RSS、启动和分发体积，SDK 对照单列。证明完整保留链和闭环已完成，不能拿改阈值诊断版、一个尺寸目标或自重建代替。

## 依赖与启动顺序

首要工作是 T02 的共同基础与 T10 的必要执行形态，T01 同步提供证据，T03 核查状态及收敛。T02/T10/T05 按具体基础能力和消费者共同设计、分批整合；T10 不等待 T08/T09 的特化与消除。T04/T05 按对应入口和支持体完成反馈，T13 从各项开始时准备真实源码验收。

```text
T02 共同基础 → T10 必要调用/存储/类型形态 ─┐
T02/T03 → T04 入口生命周期 ──────────────┼→ T05 共同编译循环 → T13
T03 状态摘要 ───────────────────────────┘
T03/T05 → T06/T07 证明与循环、T08 特化、T09 消除 → T13
T02/T04/T10 → T11 根/metadata → T12 机器位置成本 → T13
T01 贯穿提供证据。
```

C10/C11/C13 可按各自依赖独立推进。并行方式、整合责任和受阻处理遵循 [workflow](workflow.md)，任务优先级不改变当前授权。
