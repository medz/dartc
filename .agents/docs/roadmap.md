# 目标与里程碑

目标是完整实现约定范围内的 Dart 语法、可观察语义与标准库；适用规范、支持和排除范围只在 [specs](../../specs/README.md) 维护。
阶段目标不代替能力验收，也不授予开工或发布权限。任务状态、依赖和执行归属只在[看板](board.md)维护。

## 共同基础与完整编译

首先落实[共同基础合同](layout.md#基础能力先统一)：用户、std、runtime 共用 FFI/C 基础，
必要执行的实现质量与可推导短路径分别成立。基础表示、调用、存储、类型与算法均接受审查，源码 API 不决定机器模型。
语义分析、执行形态选择、生成支持和程序改写须共同闭合；默认 Compiler/CLI 消费完整结果。

| 交付方向 | 任务 |
| --- | --- |
| 可追溯的默认基线、行为和产物组成 | [T01](board.md#t01) |
| 共同基础与必要调用、存储、类型形态 | [T02](board.md#t02)、[T10](board.md#t10) |
| 收敛的状态摘要和真实入口生命周期 | [T03](board.md#t03)、[T04](board.md#t04) |
| 执行形态与程序改写的共同循环 | [T05](board.md#t05) |
| 返回/分支/循环证明、残余特化与一般对象消除 | [T06](board.md#t06) 至 [T09](board.md#t09) |
| 根、栈、metadata 与机器位置成本 | [T11](board.md#t11)、[T12](board.md#t12) |
| 默认产品的完整源码、行为和同任务成本验收 | [T13](board.md#t13) |

T02/T10 是基础主线，不能等待特化或对象消除来绕开必要执行。其余依赖按可消费合同推进，具体顺序只由看板维护。

## 完整标准库与互操作

以看板 C01–C17 的真实消费者补齐 RegExp、IO、事件源、线程/isolate、FFI、类型与加载等能力。
每项包含完整行为、接入与替代清理；架构重构完成不代表这些能力已经实现。

## 真实应用、自举与发行

G01/G02 以真实项目和 dartc 自身依赖驱动剩余缺口，自编译后重建并验证相同行为。
自举成功只证明相应任务，不能代表完整语言或标准库支持。
G03 交付匹配的编译器、固定源码资源、许可、平台验证、安装和引导恢复；发布须在相应授权范围内执行。
