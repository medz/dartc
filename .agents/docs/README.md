# 参与者文档

这里维护 dartc 当前的工程合同、工作安排和可复用方法，供所有参与者使用，并随仓库提交。
如果你不知道从哪里开始，直接看[当前推荐](board.md#现在从哪里开始)：它说明先解决什么、为什么、交付什么，以及是否有需要你决定的事项。
你可以直接描述目标或说“按当前推荐开始”；agent 负责核对现状、选择任务、安排依赖和交付，不要求你先理解任务编号。
参与实现时再按 [AGENTS.md](../../AGENTS.md) 读取相应合同和 skill。
设计要求不等于已实现能力，任务清单不自动授予执行权限；当前指令优先。

## 当前内容与证据

- 被替代的规定、历史任务映射、旧方案和旧测量从当前文档删除，同时修复入口与引用；不以“历史”“已废弃”的段落继续留在文档集中。
- Git 历史保存修改过程；CHANGELOG 按职责记录用户可见发布。原始实验、日志和临时原型保存在忽略的研究或构建目录，不作为参与者必须拥有的文档依赖。
- 采用的设计结论须在其拥有者中自足。需要外部依据时引用准确的规范或固定来源；本机路径、消失的临时文件和未公开候选不能支撑共同合同。
- 行为或性能声明绑定实际源码、输入、配置和产物。只读源码核查不能写成运行验证，文档清理不能写成编译器缺陷已修复。
- 实现、审查和返工中发现新决定、共同失误或可复用方法时，按[知识维护](workflow.md#自动知识维护)自动更新现有规则、禁令或 skill，并删除冲突内容。
