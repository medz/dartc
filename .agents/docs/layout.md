# 领域与编译合同

本文规定当前架构要求，不是实现完成清单。未完成工作见[看板](board.md)，语言行为见 [specs](../../specs/README.md)。
具体 API 以公开入口和 Dartdoc 为准；代码结构、现有类名与已有 AI 实现均可依据合同和成本证据修订。

## 基础能力先统一

用户、std 和 runtime 的执行形态建立在与 FFI/C 表示共用的基础能力上：明确宽度的标量与算术、地址、
聚合布局与对齐、内存读写、控制流、参数/结果传递和调用约束。首先审查这些基础本身的正确性与生成质量；
已有 FFI、ABI、表示选择、runtime 和优化器不因已经接入而获得保留权。

Dart 声明身份、语义类型和对象身份不直接决定物理入口、存储布局或类型信息的执行表示。
在共同基础上选择满足实际程序行为的形态，保持托管引用、GC 根、异常和生命周期。
外部 FFI 边界遵守目标 C ABI；内部调用使用明确且可验证的合同，不要求所有内部调用采用外部 ABI、
所有对象改成公开 Struct 或托管值擦成裸地址。共享、实例化和布局方案按正确性及成本比较，不预定统一替代模型。

基础能力分别通过两项验收：

1. **必要执行**：运行时值变化、保留调用、活跃对象及真正多态的程序中，算法、数据结构、调用、读写、循环、指令、metadata 和编译/运行成本合理且可解释。
2. **可推导短路径**：证明充分时，程序得到特化、简化与消除，并使相应执行需求重新收敛。

两项均通过默认消费者验证。常量样例缩小、内联成功或对象消失不能代替必要执行质量；
不得禁用优化来人为制造必要执行样本。必须区分“值在运行时变化但类型已知”和“目标或类型真正多态”。
Map、Zone、Object.toString、泛型以及 runtime 自用代码均消费共同机制，不按表面 API 名称设置编译特例。
成本被放大时追到实际普通函数、闭包、存储、类型操作或异常执行的拥有者，也审查 runtime 算法和数据结构本身。

## 领域与公开入口

`lib/src/<domain>/` 拥有可独立使用的能力，`lib/<domain>.dart` 提供公开入口。
领域间使用公开 API，依赖保持无环；接口不足时修正合同，不跨域导入内部实现。
领域可以有多个有实际用途的入口，不通过总入口转导全部工具，也不为兼容旧组织保留同责壳层。

| 领域 / 公开入口 | 拥有的事实与交付 |
| --- | --- |
| [target](../../lib/target.dart) | 显式 CPU、操作系统等目标事实；宿主识别由调用方请求。 |
| [sdk](../../lib/sdk.dart) | 固定源码内容、版本身份与只读读取；不发现或下载用户 SDK。 |
| [frontend](../../lib/frontend.dart) | 官方分析会话、诊断、静态义务及语义结果到 IR 的适配。 |
| [ir](../../lib/ir.dart) | 声明身份、类型、值、控制流、effects 与验证；不含寄存器、文件偏移或 analyzer 状态。 |
| [optimizer](../../lib/optimizer.dart) | 程序事实、摘要、变换、执行需求与失效关系；不拥有机器位置。 |
| [interop](../../lib/interop.dart) | 原生注解、结构化类型/签名、绑定和 C 声明。 |
| [assembler](../../lib/assembler.dart) | 机器字段修补契约；[ARM64](../../lib/assembler/arm64.dart) 与 [x64](../../lib/assembler/x64.dart) 分别拥有实际指令编码和操作数约束。 |
| [abi](../../lib/abi.dart) | 目标签名分类、参数/结果位置、调用破坏、原生符号修饰及帧规则。 |
| [layout](../../lib/layout.dart) | 所选存储形态的大小、对齐、字段偏移、引用槽与共享布局。 |
| [codegen](../../lib/codegen.dart) | 执行形态准备、机器约束、活跃性、位置分配及发码。 |
| [object](../../lib/object.dart) | 可重定位模块、节、符号、重定位与归档；[ELF](../../lib/object/elf.dart) 和 [Mach-O](../../lib/object/mach_o.dart) 拥有相应对象编码。 |
| [linker](../../lib/linker.dart) | 符号解析、归档成员选择、最终布局、修补、加载描述与映像签名。 |
| [compiler](../../lib/compiler.dart) | 组合公开阶段、驱动完整编译、选择输出、生成头文件并保护文件交付。 |

普通运行算法归 [`sdk/runtime`](runtime.md)，不因没有 `lib/runtime.dart` 而转移给 codegen。
frontend 的官方 AST/element 依赖是明确边界；独立 IR、汇编或链接调用者无需使用 frontend。
各阶段拥有自己的输入验证和错误责任，compiler 不复制求解算法、布局或其他领域的可变状态。

## 共同编译循环

以下是必须满足的阶段合同；当前断点及其修复验收由看板维护。

```text
目标、编译环境、源码、显式链接输入与实现选择
  → frontend / lowering：静态义务、语义与来源
  → 真实入口和外部契约
  → [联合求解：可执行边、值、对象状态、别名、逃逸、调用、类型、effects
      ↔ 共同基础上的执行实现、调用/存储/类型表示选择
      ↔ 证明后的程序改写与执行需求重算
      → 新增行为携实际调用、结果、状态及异常重新分析
      → 程序或表示变化使依赖事实失效] 共同闭合
  → 冻结准备结果
  → 机器选择与合法化 → 活跃性与位置分配 → 发码及实际 PC 元数据
  → 对象 / 归档 / 链接映像
```

先完成静态义务再裁剪；未执行源码不因此免除静态错误。IR 保留求值顺序、异常、终止、身份、
别名和必要来源，不让生成阶段重新猜测源码语义。缺失正文、非法 IR 或失效分析必须明确失败。

固定图上的事实求解、程序改写后的需求重算和实现依赖闭合分别有收敛条件：

- 固定 IR 的循环/递归以可靠抽象和摘要覆盖；保守合并可以损失精度，不能遗漏行为。真实外部未知按可触及状态扩展。
- 改写依据实际程序与事实变化继续求解；函数数不变也可能改变调用、实参或状态。删除行为后重算依赖，旧保留集不能永久成为根。
- 新支持体携带真实实参、结果、类型环境、状态与异常关系进入同一程序。内部缺边不能作为 `unknownCalls` 或任意开放根掩盖；真实未知仍需正确实现。
- 表示决策引入装箱、检查、分配或桥接时，同样参加反馈；不先固化通用模型再仅靠优化逃离其成本，也不把提前展开整个 runtime 当成闭环。

每个分析/变换明确输入、前置不变量、产出事实以及保持/失效关系。阶段驱动调度实际受影响的工作。
扩展预算约束代码增长，不能截断语义求解；同一次编译中的预算与 pass 状态不因循环重置，独立编译不共享可变状态。
复用结果须有输入身份、有效期和失效依据；缓存不能替代错误的算法或职责边界。

回调地址是运行时值，不自动意味着调用目标未知。保留来源、用途和逃逸事实，按真实导出和外部契约建立开放入口。
纯机器接线可留到冻结后；会引入程序行为的支持体必须更早进入共同循环。

## 冻结与失效

准备结果绑定程序、入口、目标、环境、绑定与实现选择。只读结果不保留可变分析会话，独立调用者也遵循相同合同。
冻结后可排列码、常量、重定位和 PC 信息，不能追加未登记的语义调用或 native/helper 依赖；发现遗漏须修正拥有者。

| 变化 | 必须复核的结果 |
| --- | --- |
| 函数体、控制流或 effects | 相关程序事实、依赖、机器选择、活跃性、分配、帧与根 |
| 类型、调用、保留需求或表示 | 布局、派发、绑定、支持体、选择与根；共享槽的全部访问者一致迁移 |
| 目标、ABI、环境或实现选择 | 从最早受影响阶段重新计算，包括可能受影响的条件导入与常量 |
| 仅机器码或节地址 | PC 元数据、重定位、链接布局；若放宽引入新的破坏/调用则返回选择与分配 |

只复用能够证明仍有效的部分；不能以“保守”为由无条件重做整个 SDK 分析。
拒绝旧结果和错误目标混用是合同，具体版本标识、缓存粒度和增量算法由消费者及证据决定。

## 机器约束、存储与根

选择先明确实际操作的输入/输出、固定或重叠位置、临时寄存器、调用破坏、异常边和安全点。
分配器据此安排寄存器、栈槽、边上并行复制及活跃引用位置；发码器消费同一选择和分配结果，绑定实际 PC。
不能在分配之后才插入可能分配、抛异常或重入的调用。

ABI 依据实际保存寄存器、局部区和出参区给出帧布局，序言/尾声使用同一布局。
正常结果与异常对在对应完成边上才有效；失败边不能读取正常结果，也不能提前把尚未初始化的值报告为根。
合流、循环、critical edge、回调及重入均保持初始化、存活和并行搬运合同。
GC 根由实际引用与分配位置决定，发码不另算一套根；整数和原生地址不能靠猜测当作托管引用。

常量、普通对象、闭包 cell 与变长载荷消费一致布局。所有共享槽访问者保持物理表示、别名、追踪与语言检查一致。
初始化、late/final 检查、异常中途写入和错误对象身份按语言合同实现，零载荷不能冒充已绑定的合法值。
数值检查和修正属于可分析的语义操作；ISA 层只编码机器行为，不能把硬件异常直接当作 Dart 异常。
具体对象头、类型数据与调用策略仍接受基础合同审查。

## 裁剪、链接与交付

局部 DCE、程序摇树和链接裁剪分别消费其层次的事实。入口、导出、逃逸回调、初始化/终止、
GC/异常元数据和真实引用都须有可追溯保留原因；metadata 不能反向保活已消失的行为。
显式对象、归档和共享库遵守不同输入合同：归档按解析需要选成员，显式加载的初始化效果不能仅因无普通符号引用删除。

原生声明图服务实际调用和头文件；符号修饰只在声明到链接名的边界执行一次。
object 保留精确符号和未决引用，linker 使用同一最终布局生成地址、修补和加载描述，不在编码时重算另一份地址。
编译结果应在交付前完成其必需检查；任何输出写入前先核对全部输入/输出别名与覆盖风险。

源码资源与用户目标依赖分别管理，资源合同见 [resource-packaging](resource-packaging.md)。
验证操作见[测试说明](../../test/README.md)，各项当前验收输入与缺口只见[看板](board.md)。
