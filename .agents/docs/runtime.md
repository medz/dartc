# 标准库、运行时与原生互操作

本文规定 std、patches、runtime、受信原语、GC 与 FFI 的实现合同，不代表各项能力已经完成。
共同基础、编译循环和领域职责见[架构](layout.md)；支持范围与语义缺口只在 [specs](../../specs/README.md) 维护。
任务状态见[看板](board.md)，验证操作见[测试说明](../../test/README.md)。

## 源码与算法归属

| 位置 | 责任 | 边界 |
| --- | --- | --- |
| `sdk/std/` | 固定官方 Dart 源码、库声明与普通算法 | 保留来源和许可证；不继承其他后端的对象布局或执行模型。 |
| `sdk/patches/` | 官方声明的目标实现片段及必要存储适配 | 与原声明共同检查，不因 `external` 或内部库身份重写整套算法。 |
| `sdk/runtime/` | 分配、回收、类型关系、异常、调度及启动等运行机制 | 使用普通 Dart 与受信叶子能力，不导入编译器 IR、codegen 或 assembler。 |

遇到官方 `external`，沿声明、实现片段和普通调用继续查到实际叶子。
已有 Dart 正文、依赖特定后端的正文与真正机器能力必须分别处理。
官方原生实现的存在不等于已有可复用 Dart 实现；缺失叶子也不授权复制已有上层算法。
实现片段保留原声明身份、全部片段、默认值、初始化顺序及静态义务。
替换已有正文须有目标存储约束或规范证据，并迁移消费者、删除被替代实现。

三类源码使用同一套 Dart 类型与编译规则，真实库来源和私有可见性保留。
runtime 来源不豁免类型、效果、异常、根或声明完整性检查。
源码资源封装只交付内容，不建立第二套类型系统、预编译 runtime 或专用编译链。
缺失固定资源必须失败，不能静默转向用户 SDK、网络下载或其他版本。

## 共同基础上的运行机制

共同表示、必要执行与可推导短路径遵循[基础合同](layout.md#基础能力先统一)。
普通 Pointer、Struct/Union、Array 与 runtime 存储共用宽度、对齐和访问规则。

分配策略、对象遍历、类型相等/哈希/子类型、异常搜索和调度算法由普通 Dart 表达。
机器层只承担必要语义转换、不可表达的机器能力及调用、根、栈、布局接点。
不能把整个库方法或算法改名为原语，也不能按 Map、Zone、Object.toString 等表面 API 建专用路径。
普通 Dart 实现本身不证明生成质量合理；必须检查实际调用、存储、类型操作与循环。

## 受信声明与外部效果

受信声明定义见 [`lib/runtime/contracts.dart`](../../lib/runtime/contracts.dart)。
声明识别由 [RuntimeDeclarations](../../lib/src/frontend/runtime_declarations.dart) 负责，
绑定由 [compiler/runtime](../../lib/src/compiler/runtime.dart) 负责；以声明身份与合法来源核验，不按显示名称授信。

- `RuntimeEntry` 连接受信声明与普通 Dart 正文；缺失、重复或签名不兼容必须拒绝。
- `Primitive` 只表示普通 Dart 和共同 FFI 基础仍无法表达的必要能力。
- `SystemNative` 将受信系统声明接入目标库；普通原生函数使用共同 FFI 绑定与调用合同。
- `NonAllocating` 约束完整调用闭包；对外部实现的显式承诺不等于编译器证明了其正文。

每项外部能力明确参数、结果、内存读写、可触及状态、分配、异常、重入、终止与失败方式。
纯内存不变不代表无 IO；`isLeaf` 不代表纯函数，也不替代禁止分配或重入的合同。
来自真实外部输入的不确定性必须正确覆盖；丢失正文、调用参数或阶段事实不能伪装成外部不确定性。
生成的装箱、检查、桥接与 runtime 调用须携带实际依赖和效果进入架构规定的共同编译循环。

## GC、控制存储与引用

GC 的语义责任是保留活跃对象、身份、别名、弱引用与终结契约；具体算法和数据结构可替换。
对象描述符、引用槽和根记录由其布局拥有者定义，runtime 与机器层消费同一份事实。
托管引用、原生指针、标量与对象内部地址分别保留语义，不能靠猜测机器字扫描根。

bootstrap、控制存储、托管堆与收集关键期须有明确的分配、扫描、失败和释放合同。
控制状态不能依赖正在收集的用户堆才能继续工作，也不能演变为另一套语言规则。
控制存储中持有的托管引用必须显式纳入根扫描，不能因控制对象自身不被回收而遗漏其引用。
初始化与页登记失败必须撤销本次持有资源；失败路径不得递归分配错误对象或依赖未完成的初始化。

收集关键期的实际调用闭包不得触发依赖该次收集的托管分配、Dart 异常或 Dart 重入。
检查涵盖 Pointer 包装、装箱、闭包、异常构造、原生调用及后期插入的辅助操作。
必要的非托管分配及其失败处理独立描述；效果不满足时拒绝生成，不回退为隐藏手写算法。
当前检查入口是 [ProgramSelection.checkNonAllocating](../../lib/src/codegen/program_selection.dart)。

根在可能收集或重入前发布，并覆盖全局、活跃栈帧、挂起状态与暂停的外层调用。
根位置由实际存活和机器分配确定；runtime 根据有效描述符访问，不重算寄存器或栈位置。
内部地址须限定允许存活的阶段并保留拥有者；若引入移动回收，同批更新地址有效期、根更新与重载合同。
弱引用清空时机不能用普通分配压力推定；收集行为与语言允许的非确定性分开判断。

## 生命周期、调度与终结

进程入口、持久模块、同步重入和卸载各自拥有明确的状态与资源生命周期。
入口合同包括初始化、失败重试、待处理工作、退出码、异常退出和释放责任。
重复库入口不能按全零新进程分析；重入必须保留外层根和同一状态拥有者。
进程立即退出与正常清理不能混为一谈，异步宿主驱动与跨线程进入也不能由同步重入推定支持。

调度保留微任务、事件、Timer 与 Zone 的可观察顺序及错误传播。
终结记录在收集关键期只更新状态与引用关系，用户回调在允许执行用户代码的阶段交付。
Dart Finalizer、NativeFinalizer、Finalizable 的存活、线程、解绑和退出义务分别遵守公开契约；
不能用一种终结器的行为代替另一种，也不能为触发回收改变语言承诺。
关闭或卸载必须终止对应资源生命周期，不允许在已释放上下文中继续回调。

## FFI 边界与资源所有权

FFI 使用 `dart:ffi` 的原生类型和显式目标布局；不得从宿主 `sizeOf` 推导目标数据。
固定宽度整数与指针宽度整数分别处理，字段、数组、位宽、对齐和重叠访问保持同一规则。
原生签名、参数/结果分类、调用破坏和栈规则由 ABI 的共同事实驱动调用双方。
聚合值可对应多个寄存器片段、栈区域或间接结果；不能只按总大小或单个结果寄存器分类。
平台差异必须按目标处理，不向原生边界输出私有托管布局。

内部 Dart 调用保持 Dart 值与异常语义；原生边界才执行其规定的截断、扩展、Float 舍入等转换。
类型化指针不自动证明地址有效、容量足够或生命周期安全。
接口明确长度/容量、借用或转移、别名、有效期、释放者、回调线程及重入规则。
隐藏原生布局可用 Opaque 与创建/使用/释放操作；不能直接暴露可移动托管对象地址。
托管值跨模块或外部边界须另有身份、根、拥有者和卸载合同，裸地址不构成该合同。

回调创建、调用、异常返回和关闭形成一个完整消费者，关闭竞争与异线程进入按各自契约处理。
头文件与实际调用共用原生声明图及布局，包含引用到的结构、联合、函数指针和准确原型。
C/C++ 可包含的头文件不等于支持任意 C++ ABI；不为头文件维护另一份偏移模型。
