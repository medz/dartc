# 编译器源码资源

本页规定源码资源的内容、读取、可执行容器与交付责任。
资源格式不决定用户程序的执行形态；算法归属见 [runtime](runtime.md)，共同编译合同见[架构](layout.md)。
实现入口与限制在下文链接到源码；修改容器或升级宿主 SDK 后须重新验证，不能将旧实现当作永久平台接口。

## 内容与身份

资源由固定官方标准库、runtime、patches 及其实际导入的共享契约组成。
目录说明见 [`sdk/README.md`](../../sdk/README.md)，文件集合由 [SourceDirectory](../../lib/src/sdk/sdk_sources.dart) 定义。
保留库配置、part/导入所需文件、版本标识与许可证，不按宿主编译器代码的可达性裁剪源码。
Unicode 数据的源码视图包含派生 Dart 常量和许可证；原始生成输入不作为运行时文件交付。

```text
manifest.json       归档格式与逐文件摘要
sdk/std/            固定官方源码、版本、修订与许可证
sdk/runtime/        普通 Dart 运行机制
sdk/patches/        目标实现与派生常量
lib/...             源码实际使用的共享声明与布局契约
```

[DartSdk](../../lib/src/sdk/sdk.dart) 校验标准库版本、修订和内容指纹，固定值以该源码为准。
SDK 更新须同时更新官方文件与 pin，不能只修改版本字符串。
缺失、损坏或版本不符必须失败，不转向用户安装的 SDK、其他源码版本或网络下载。
生成 ZIP 是构建产物，不提交仓库；源码包仍须携带完整资源及生成所需输入。

## ZIP 与读取合同

[SourceArchive](../../lib/src/sdk/source_archive.dart) 使用 ZIP，编码端采用 Deflate。
`manifest.json` 的 `format` 为当前格式版本，`files` 将每个文件路径映射到 SHA-256。
编码固定文件顺序、权限、时间字段和压缩参数，不写本机绝对路径或构建时间。
格式变更应迁移全部消费者；确定性编码不代表某种压缩格式具有性能优势。

构造归档视图时校验中央目录、manifest、路径集合与摘要格式，不建立全量源码字符串 Map。
提供 `digest` 时先检查压缩载荷 SHA-256；`read` 再核对所请求文件的大小、CRC 与内容 SHA-256。
manifest 按 UTF-8 JSON 解码；普通文件返回只读字节，源码解码由其消费者承担。
目录视图的指纹读取实际内容，归档指纹使用 manifest 的逐文件摘要；二者采用相同路径排序合同。
归档指纹本身不代替逐文件校验，载荷摘要也不代替发行签名的真实性保证。

读取拒绝重复路径、绝对或越界路径、链接、文件/目录冲突、加密条目和不支持的压缩形式。
中央目录、条目数量、压缩/展开总量及单文件大小均受检查；具体上限以 SourceArchive 为准。
非法格式、截断与校验失败必须显式报错，不能依赖解码器覆盖重复名称或容忍损坏的默认行为。
SourceDirectory 同样限制可读根与共享文件，并拒绝符号链接越出资源树。

## 宿主可执行容器

[ExecutableResources](../../lib/src/linker/executable_resources.dart) 根据宿主映像识别容器，不使用用户程序的输出 Target。
当前实现处理受限的 64 位 Linux ELF 和单架构 macOS Mach-O SDK AOT 映像；其他布局明确拒绝。
定位记录包含 magic、版本、ZIP 文件偏移和长度，采用小端编码，并检查范围与对齐填充。
读取只取定位记录和有界资源段，不扫描整个文件寻找 magic，也不把整个映像交给 ZIP 解码器。
字段宽度、载荷上限及具体容器检查以实现为准，不能凭文件扩展名或平台名称推定兼容。

| 宿主格式 | 资源位置与必须保持的内容 |
| --- | --- |
| ELF | 在 SDK 快照尾标之前加入 ZIP、填充和定位记录；将原尾标保留在文件末尾，快照起点与正文不变。 |
| Mach-O | 在原尾部签名之前加入资源和定位记录；保留 SDK 快照 note 及原内容位置，扩展 `__LINKEDIT` 并重写签名位置。 |

Mach-O 仅允许实现已识别的 ad-hoc 签名与受限附属记录，不能丢弃签名要求或 entitlement。
封装重建覆盖资源与定位记录的签名；不支持任意二进制重签、fat 映像或任意发行签名输入。
资源封装应先于最终发行签名；后续签名若调整布局，须重新验证资源定位、系统签名检查与启动。
不能仅凭自己的容器读取器读回成功就宣布系统能够加载执行。

封装 API 返回新映像，保留原输入；重复封装和不支持布局必须失败。
构建方负责在目标目录准备临时产物，保留可执行权限，校验后提交输出并清理临时文件。
宿主 SDK 的容器布局是外部依赖，升级时须用实际产物核对上述约束。

## 构建与消费者

[buildCompiler](../../tool/src/compiler_build.dart) 先生成资源归档，检查 DartSdk 身份并读取全部文件验证内容，
再用官方 SDK 编译宿主，将归档摘要绑定到 `dartc.resources` 构建常量，封装并核对读回载荷摘要。
官方 SDK 在这里构建宿主；资源封装不生成 runtime IR、预编译 runtime 或源码字符串载体。
编译用户程序时仍由 dartc 读取资源并执行自己的编译流程，普通用户产物不附带整份源码 ZIP。

| 消费者 | 内容来源与责任 |
| --- | --- |
| 源码运行与开发 | `SdkSources.load()` 通过 dartc 包位置取得 SourceDirectory；不探测工作目录、PATH 或用户 SDK。源码变更无需先生成归档。 |
| 独立 CLI | [命令入口](../../lib/src/compiler/cli/command.dart) 依据嵌入摘要选择自身资源并校验；帮助路径不要求打开资源。 |
| 库调用与第三方 AOT 宿主 | 显式向 `Compiler(resources: ...)` 提供 SdkSources，并负责资源交付与定位；AOT 构建不会自动包含任意源码文件。 |

公共输入由 [`package:dartc/sdk.dart`](../../lib/sdk.dart) 暴露，目录和归档提供相同的列举、存在性、长度与单文件读取接口。
容器、压缩与源码供给差异不应渗入语义分析，不以新增后备查找链掩盖缺失资源。

## 验证责任

资源提供者验证确定性、原字节一致、来源限制、逐文件读取和损坏拒绝；对应入口为 [test/sdk](../../test/sdk)。
构建与容器消费者验证摘要绑定、重复封装拒绝、快照保留、资源范围、权限及签名限制。
独立编译器须移离源码树后离线启动并编译固定输入；库消费者另行验证显式资源供给。
系统加载与执行须在受影响宿主平台验证，模拟执行与硬件性能分开报告。
签名或启动没有实际执行证据时保持未验证，不能从支持的平台枚举或旧版本结果推导通过。
检查范围、资产准备和复用方式遵循[测试说明](../../test/README.md)与[工作流](workflow.md)，不重复运行无关编译器矩阵。
